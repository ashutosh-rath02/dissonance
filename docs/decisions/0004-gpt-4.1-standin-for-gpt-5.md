# ADR 0004: gpt-4.1(-mini) as a stand-in for gpt-5(-mini)

## Status
Accepted (2026-07-17) — temporary, revisit once org verification completes.

## Context
`configs/run.yaml` originally pointed the cheap/strong tiers at `gpt-5-mini`/`gpt-5`. Both models
are listed by `client.models.list()` for this API key, but calling them returns
`404 model_not_found`: "Your organization must be verified to use the model `gpt-5-mini`."
(`platform.openai.com/settings/organization/general` → Verify Organization, ~15min to propagate).
`gpt-4.1-mini`/`gpt-4.1` work immediately with the same key.

## Decision
Point `models.cheap`/`models.strong` in `configs/run.yaml` at `gpt-4.1-mini`/`gpt-4.1` until the
org is verified, then swap `name` back to `gpt-5-mini`/`gpt-5`.

## Rationale
- Everything downstream (`ModelTierConfig`, `Extractor`, escalation logic) is keyed off the config
  file's tier names ("cheap"/"strong"), not model names — swapping `name` is a one-line change
  with no code changes required.
- Blocking Week 2 on an external verification step (only the account owner can do it, and it's a
  wait-and-see propagation delay) isn't worth it when a same-family, similarly-priced model
  unblocks extraction today.

## Consequences
- `price_per_1m_*` in `run.yaml` reflect gpt-4.1 pricing, not gpt-5 pricing, until swapped back —
  don't forget to update both `name` and pricing together.
- Any extraction quality numbers recorded before the swap (Week 3 golden-set evals) were produced
  against gpt-4.1(-mini), not gpt-5(-mini) — note this in `evals/report.py` output if the swap
  happens mid-harness so numbers aren't silently attributed to the wrong model.
